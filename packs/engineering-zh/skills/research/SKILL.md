# 调研

调研的产出不是一段回答，而是仓库里一份别人（包括下一个你）能直接引用的笔记。

## 什么算一手来源

一手来源是信息的原始出处：官方文档、规范正文、源码与其提交历史、第一方 API 说明、官方变更日志（changelog）与发布说明、作者本人的原始文章。

二手来源是别人消化过的转述：博客、教程站、问答社区、聚合文章、AI 生成的摘要。它们有用，用途只有一个——**帮你在几十秒内找到一手来源的入口**。凡是写进笔记的结论，都要能指回一手来源。

判断方法：你引用的那句话，是不是由定义这个行为的人写下的？不是，就再往上找一层。

来源之间打架（文档与源码不一致、旧版本文档还在网上）时，以源码或当前版本的规范为准，并在笔记里写明这个分歧。

## 派出去

用 `subagent` 工具发起，一个子代理查一个具体问题，**在同一条消息里并行发起多个**，不要串成一条链。问题之间没有依赖时并行，有依赖时先查清前置再派下一个。

派出去的提示词里写清四件事：

- 要回答的具体问题，一次只问一个
- 什么算一手来源，允许它先靠二手来源找入口
- 笔记写到哪里、叫什么名字
- 结论要短，但每条结论后面必须挂出处

派完不要等。继续做手里与它无关的活，结果回来会有通知。

## 为什么落成文件

写进对话的结论只能活在这次的上下文里：上下文一压就没了，下一个会话看不见，人也没法改、没法引用、没法在旁边批注。

写进文件的结论可以被后面的票据、规格、提交直接引用，可以被逐条怀疑和更正，也可以在半年后拿来看还成不成立。文件是这份调研的唯一交付物，聊天里那句「查完了」不算。

## 笔记里写四块

- **结论**：每条一到两句话，能直接拿去用的话。开头就把答案放在这里。
- **依据**：这条结论是从哪句原文、哪段代码、哪次运行推出来的。写下推理的落点，不写搜索过程。
- **出处**：来源链接、版本号、查证日期。版本号尤其重要，同一个东西不同版本行为不一样。
- **还没确定的**：查不到、来源互相矛盾、只有二手来源支撑的部分明确列出来。留着比删掉更有价值——它告诉下一个人该从哪接着查。

每块都只写事实。不确定就写不确定，不要用听起来合理的推测把它填满。

## 调研出来的是素材

笔记里的东西是拿去做决定的原料，不是决定本身。

它没有考虑你项目的约束、已有代码的样子、团队愿意承担的维护成本。要用它的人还需要自己判断：这条现在成立吗、适用我们这个版本吗、代价我们扛不扛得住。

所以写笔记时把「事实」和「建议」分开放。看到建议的人得知道哪句是来源说的，哪句是查资料的人顺手加的判断。

## 算完了

- 结论一眼能看到，且每条都指得回一手来源
- 版本号和查证日期都写了
- 不确定的部分列出来了，没被含糊的话盖住
- 文件在仓库里，路径写在回复里
