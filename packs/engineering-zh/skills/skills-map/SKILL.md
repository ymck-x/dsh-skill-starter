# 技能路由表

这张表只做定位，用来回答「现在该加载哪一个」。解释某个技能具体怎么做之前，先读那个技能自己的文件：用 `skill` 工具加载它，或直接读 `~/.dsh/skills/<名字>/SKILL.md`。下面的摘要不替代它。

## 二、主流程怎么串

一条从想法到上线的路，四步各管一段，每步都有能判定的收工标志：

1. `grilling`：一轮问一批，把含糊处一个个逼掉。收工标志是没有「大概」「看情况」这类答案还挂着。
2. `to-spec`：把聊定的结论写成规格。收工标志是规格里每条要求都能判定做完没做完。
3. `to-tickets`：拆成能各自独立收工的票据，声明「阻塞于 #N」。收工标志是每张票都能单独开工、单独验收。
4. `implement`：按票据逐张做，测试先行，做完一张就审查并提交。收工标志是票据状态走到 `已完成`、改动已提交。
5. `code-review` 与 `pr`：审查通过就写 PR 正文收尾。

分叉判断：

- 结论还没定 → 回 `grilling`，不要硬写规格。
- 只想先看清方案的样子，不想产出真代码 → `prototype`，拿到答案就丢掉那份代码。
- 下一步被票据挡住 → 先做被阻塞那张，不要绕过阻塞关系。
- 主流程是给「新功能、可预期的工作」用的。修不确定的坏东西走旁路，见下一节。

## 三、旁路入口

每条旁路自成一体，做完回到主流程对应位置。

- `diagnosing-bugs`：东西坏了、跑得慢、行为不对。这里的入场条件是先拿到一条能对这个问题变红的反馈回路，没拿到就只做这一件事，不猜原因。
- `improve-codebase-architecture`：手里没有具体活，想定期扫一遍结构机会，产出候选让用户挑。
- `prototype`：设计问题纸上说不清，写一次性代码把答案跑出来，答案落进规格或票据，代码丢掉。
- `research`：查资料的体力活交给后台子代理，留下一份带引用的笔记。
- `retro`：一次构建做完之后，回看这段会话，给工作环境提改进建议。

## 四、词汇层怎么垫

词汇层不单独跑流程，它垫在其他技能下面提供说法。写规格、拆票、设计接口时按需加载：

- `codebase-design`：深模块、缝、量深度。
- `domain-modeling`：项目术语表与架构决策记录。

主流程技能和它们不冲突，可以同时加载。

## 五、独立技能

不串进上面任何一条链，按需单点使用：

- `handoff`：把会话压成交接文档。
- `to-questionnaire`：写问卷去问别人。
- `wait-what`：把上一条消息用大白话重讲。
- `teach`：跨多次会话学一门概念，当前目录当教室。
- `writing-for-agents`：写技能、写 `AGENTS.md` 这类给模型读的文档。

## 六、只能人工发起的九个

这九个模型不能自己调用，需要用户手打 `/名字`：`handoff`、`implement`、`teach`、`to-spec`、`to-tickets`、`to-questionnaire`、`wait-what`、`retro`、`improve-codebase-architecture`。其余技能模型可以自己加载。

原因是它们会改变工作状态或开支线，而不只是消耗一次回答：`to-spec`、`to-tickets`、`implement` 会往票据目录写入并推进票据状态；`handoff`、`teach` 会开启跨越机器或跨越多次会话的新流程；`to-questionnaire`、`retro`、`improve-codebase-architecture` 要么对外发东西，要么给工作环境留下长期改动；`wait-what` 是用户对自己是否听懂的判断，模型替不了。

模型遇到这些处境时，说明该用哪个技能，让用户自己发起。

## 七、怎么加载技能

方式一：用 `skill` 工具，参数填技能名。

方式二：直接读 `~/.dsh/skills/<名字>/SKILL.md`。

一个处境可能需要多个技能，一次把相关的都加载进来（例如 `implement` 配 `codebase-design`）。

## 八、票据和规格放哪

- 一个文件一张：`docs/agents/tickets/<编号>-<短名>.md`，编号从 1 递增。
- 依赖写在文件里：「阻塞于 #N」。
- 文件顶部一行状态：`待确认` / `已就绪` / `进行中` / `已完成`。
- 票据约定本身写在 `docs/agents/issue-tracker.md`。

`docs/agents/issue-tracker.md` 不存在时，先加载 `setup-tickets` 把约定建好，再走 `to-spec`、`to-tickets`、`implement`。

要判断该继续、开新会话、做交接还是派子代理时，读同目录的 `PHASE-BOUNDARIES.md`：判断时机、四个选项各自的可观察信号、一手材料与二手材料的有损交易。
