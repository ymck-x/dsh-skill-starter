# 教室工作区：跨会话状态落到哪些文件

教室就是当前工作目录。跨会话靠的不是记忆，是这里固定名字、固定编号的一组文件。开课时先把骨架建起来，之后每节课只往里追加。下面每条规则后面写清理由，以及漏掉之后会发生什么。

## 一、教室的布局与命名

```
<教室>/
├── 立意.md                  # 为什么学、学成什么样算成功、约束、范围外
├── 来源.md                  # 知识类与社区类来源，含缺口
├── 词汇表.md                # 一个词一句话，只收已理解的词
├── 课程/
│   └── 0001-<短名>.html     # 每节课一份，双击可打开
├── 记录/
│   └── 0001-<短名>.md       # 一条学习记录一个文件
├── 资料/
│   └── <来源短名>.md        # 从来源裁出来的摘录、例子
├── 笔记/
│   └── <主题短名>.md        # 摸索过程、待查问题
└── 组件/
    ├── 样式.css             # 所有课程共用的样式
    └── 自测.js              # 判分、折叠答案等共用交互
```

| 文件 | 承载什么 | 命名规则 |
|---|---|---|
| `立意.md` | 为什么学、成功的样子、时间与基础约束、明确划掉的范围 | 固定名，一份；改内容不改名 |
| `来源.md` | 每类来源一条，后面注明拿它干嘛（主线 / 查细节 / 问理解 / 问报错）；缺口明写 | 固定名，一份 |
| `课程/0001-<短名>.html` | 一节课的复习、讲解、自测 | 四位递增编号加短名，如 `0007-闭包捕获什么.html` |
| `记录/0001-<短名>.md` | 一条学习记录 | 同一套编号规则，独立递增，如 `0012-闭包捕获的是变量.md` |
| `资料/<来源短名>.md` | 原文摘录、最小例子、章节要点，开头一行写出处与链接 | 按来源起名，如 `mdn-闭包.md`；同一来源追加进同一份 |
| `笔记/<主题短名>.md` | 你的摸索、对照表、待查问题 | 按主题起名，同类归一份，标题里标 `待验证` 或 `已确认` |
| `词汇表.md` | 一个词一句话的解释 | 固定名，一份，按拼音或字母排序 |
| `组件/样式.css`、`组件/自测.js` | 判分、折叠、进度等共用交互 | 固定名，一份；新组件先加进来，再在课里引用 |

课程编号是「第几节课」，记录编号是「第几条记录」，两套各自从 0001 递增。

## 二、为什么名字和编号要固定

- **跨会话接手不用猜**：下次开课第一件事就是读文件。名字固定时一眼知道读哪几份；名字随心情起，就得先把目录翻一遍，再猜哪份是立意、哪份是草稿。
- **编号把顺序找回来**：`课程/`、`记录/` 排一下序就是时间线，不依赖文件修改时间——复制、同步、重建目录都会把时间戳改掉。
- **引用不会断**：课程文件里可以写「回看 `记录/0009-…`」，编号稳定，这句话一年后仍然指得准。
- **违反的后果是静默的**：文件都在，只是接手的人读错了那份，于是把已经纠正过的误解当成还没纠正，重新讲一遍；或者把第三条课当成最新一节，跳过了两节前置。

## 三、学习记录只增不改

一条记录落地就是历史，改写它等于改证据。写错了按这三步处理：

1. 新建 `记录/<下一个编号>-<短名>.md`，正文第一行写「取代 #旧编号」，第二行写正确的那条结论。
2. 回到旧文件末尾追加一行「已被 #新编号 取代」，旧文件里原来的字句留在原地。
3. 同步改 `词汇表.md` 里受影响的那条。

这样做的原因：学习记录的价值一半在内容，一半在「从错到对」的轨迹。复习时旧记录正好是一道好题——「你当时是这么想的，错在哪」。直接删改，轨迹就没了；下一次接手的人也分不清眼前是「还没学」还是「学错了又改对了」，只能重讲一遍。

## 四、记录里只放这两种东西

一条合格的学习记录，要么是你用自己的话把某个机制讲对了，要么是一个误解被纠正并写清原来错在哪。

| 常见写法 | 它的去处 | 这样安排的理由 |
|---|---|---|
| 今天讲了闭包、柯里化、装饰器 | 课程文件已经记了这节课讲什么 | 课堂内容不是你会的证据；写进去会让记录变长，真正的进展被埋掉 |
| 从文档抄下来的定义 | `资料/` 或 `词汇表.md` | 抄写不产生理解，跨会话时它证明不了你会 |
| 「大概是这样」「估计是因为…」 | `笔记/<主题>.md`，并标 `待验证` | 推测和已确认的理解混在一起，下次复习会把错的当对的背下来 |
| 你答对但还讲不出来的题 | 留它在课程文件的自测里，等你能用自己的话讲一遍再记 | 记录的门槛是能复述；门槛一降，记录就不再是进度表 |
| 已经收进词汇表的词再说一遍 | `词汇表.md` 对应那一行 | 同一条事实占两处，改的时候必然漏一处，之后两份开始互相矛盾 |

## 五、测验的线索设计

题目考判断，不考排除。每条设计对应一个会漏的分数：

| 规则 | 为什么 |
|---|---|
| 所有选项长度、字数大致相同 | 正确答案明显最长时，你靠长度就能选对，这道题变成阅读理解 |
| 正确答案的位置在题目之间变化，A、B、C、D 都出现过 | 位置有规律时，你记住的是位置，不是它为什么对 |
| 干扰项取自真实会犯的错：漏边界条件、混淆两个相似概念 | 一眼假的选项让题目只剩两个候选，考不出任何判断 |
| 题干和选项里不重复答案的用词 | 题干出现选项里的原词，你按字面匹配就能选对，理解没有参与 |
| 同一次自测里混排主题与题型 | 按块出题时靠惯性就能答，交错出题才逼出「该用哪一招」的判断 |
| 选项里不放「以上都对」「以上都不是」 | 判断出一个错的就能排除整组，题失效 |

## 六、一节课的文件结构

一份课程 HTML 从上到下固定三段：

- **开头复习**：先出三到五个旧问题，答案折叠在后面。放上次做错的、上次留了回访时间的、这节要用到的前置；你先写完，再展开对照。
- **中间讲解**：最短的一段，够建立正确印象——一个定义、一个最小例子、一到两道现场判断题，紧接着一组练习题，答案与解析都折叠。
- **结尾自测**：五到八道题，按第五节的线索规则出；末尾写清「学完这节你应该能用自己的话回答……」，并留一行写下下次回访的时间与从那一条开始。
- **共用组件**：样式与判分全部从 `组件/` 取，这节课新增的交互先补进 `组件/`，再在页面里引用。

## 七、下次开课按顺序读这几份

1. `立意.md`——确认目标没变；变了就先改立意，再排新内容。
2. `记录/` 里编号最大的三条，加上上一节课末尾写的回访清单——决定这节课从哪一条接着讲。
3. `词汇表.md`——拿已收的词做开头的提取练习。
4. `来源.md`——挑这节课要用的来源；缺口那几条按提示去补。
5. `课程/` 里编号最大的那份——看上次讲到哪、哪些题没答完。
6. `组件/`——这节课要用的新交互先补进来。

读完这六份，你对「上次到哪、这节教什么、用什么教」三件事都有答案，然后动手写 `课程/<下一个编号>-<短名>.html`。
