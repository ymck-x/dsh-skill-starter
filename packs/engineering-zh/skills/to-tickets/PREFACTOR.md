# 预重构与票据样例

这份附件承载「预重构（prefactor）」的做法，以及一张填好的票据文件长什么样。拆票时遇到「同一处这次要改好几遍」「每一刀都切不干净」，先读这里，判断要不要插一张预重构票、它排在哪、怎么证明行为没变。票据的字段与编号约定仍以 `docs/agents/issue-tracker.md` 为准。

## 一、什么叫预重构

先让这次改动变简单，再去做这个已经变简单的改动。

顺序反过来的代价：直接动手时，每一刀同时背着两个目标——改行为、绕开旧结构，两者互相拖，影响半径越滚越大。预重构把顺序拆成两个各自能验证的步骤：第一步只动结构，第二步在这个干净的结构上改行为。

一句话口径：预重构不交付用户能看见的变化，它交付的是「下一步改动变便宜」。

## 二、什么时候值得做

出现下面任一条，就插一张预重构票：

- **同一处代码这次要改三遍以上**：三处调用点、三个分支、三段复制粘贴的相似逻辑，全落在这次改动里。
- **当前结构让每一刀都切不干净**：动一处就必须顺手改另一处，才能编译或跑通。
- **改完还要再拆一次**：按现在的结构，这次改动自己就得先铺成扩张-收缩那种多票一组。
- **同一组判断条件散落在多个位置**：改一处会漏另一处。
- **名字与概念对不上**：领域里的概念在代码里只是一堆裸参数、裸字符串，新行为无处可放。

对照着收手：只碰一处、只改一次、结构本来就贴着概念，直接改，不必插票。

## 三、怎么排期

预重构自己就是一张票据，和别的票同格式、同编号序列、同目录。

1. 给它一个普通编号，标题以「预重构：」开头，一眼能与行为改动区分开。
2. 状态写 `已就绪`，让执行者能立刻开工。
3. 让所有依赖它的票据写「阻塞于 #N」，指向这张预重构票。
4. 在依赖它的票面上补一行：本次改动在预重构之后变简单的那个点是什么。
5. 把预重构排在所有依赖它的票据之前，中间不夹无关的票。

预重构票自己通常写「阻塞于 无」。它落地之后，依赖它的那批票一起解锁，按各自的阻塞关系并行开工。多个预重构之间互不依赖时，同样并行。

## 四、边界：只调结构，保持行为

预重构的唯一产物是结构改变，行为逐条保持原样。这条承诺靠现有反馈回路兑现：

1. **先跑一遍现有回路**，把当前结果逐条记下来，包括本来就允许失败的那几条。
2. **按结构动作改代码**，一次一个动作。
3. **重跑同一套回路**，结果与第一步逐条一致，这一步才算完成。
4. **给新结构补一条测试**，证明新概念本身立得住。

回路薄的地方先补一层：把接口契约测试、快照、端到端脚本拿来当行为基线。基线跑不起来或结果不稳定时，先做一张「补反馈回路」的票，再回来做预重构。

验收口径：改动前后同一套回路逐条同结果，且新结构上有一处只有它能回答的测试。

## 五、哪些动作算预重构

- **提取函数**：把一段有意图的行为从长函数里搬出来，给它一个说清意图的名字。
- **把参数收成一个对象**：一组总是一起出现的参数收成一个概念，调用点少一处漏传的机会。
- **把散落的条件收成一处**：同一组判断条件归到一个决策点，由它一处回答。
- **给领域概念建立类型**：用有名字的类型替掉裸字符串、裸整数，让非法状态构造不出来。
- **先给概念定名**：概念还没定型时，先在词汇层（`GLOSSARY.md`）定名定边界，再动结构。

这些都是纯结构动作。往动作里夹一次行为修正，它就降级成普通票据，行为基线同时失效。

## 六、填好的票据文件样例

文件：`docs/agents/tickets/4-prefactor-refundable-order.md`

```markdown
# 4 预重构：把「能不能退」的判断收成一处

状态：已就绪
阻塞于：无

## 要构建什么
退款资格今天由三处各自回答。把「这张订单现在能不能退」收成一个领域概念，由它一处回答。判定结果与今天逐条一致，用户看得见的行为这次不变。

## 反馈回路
`pnpm test refund` 在改动前后都全绿。
新增一条测试只覆盖这个新概念：可退、超出窗口、已撤销三种输入各一例。

## 验收标准
- 同一套退款回路在改动前后逐条同结果。
- 新概念上有自己的测试，且这条测试在旧结构上写不出来。
- 三处调用点里不再各自出现金额、窗口、撤销的判断条件。
- 退款接口的响应与改动前逐字段相同。

## 不在这一票里
窗口长度、退款步骤、订单状态机原样保留，留给后面那批票处理。
```

各部分为什么这么写：

- **标题与编号**：走普通编号序列，同时用「预重构：」标出它属于结构类，执行者一眼知道验收口径是行为不变。
- **状态行**：单独一行放最上面，`已就绪` 表示可以直接开工，不必回头问人；沿用 `待确认` / `已就绪` / `进行中` / `已完成` 四个词。
- **阻塞于**：写「无」。预重构通常不依赖别的票，它自己是被依赖的一方。
- **要构建什么**：写结构目标加一句行为保持不变的承诺，只写决策本身，具体文件路径与代码片段留给执行者自己定位。
- **反馈回路**：给出那条能变红变绿的命令，让执行者自己判定做完没有；再加一条只针对新概念的测试，把结构立得住这件事也变成可判定的。
- **验收标准**：每条都能当场判定。前两条证明行为没变、新结构立得住；后两条证明下一步改动真的变简单了，也就是这张票值回票价。
- **不在这一票里**：把边界钉在票面上，顺手的行为改动有地方可放——放进后面那批票。
