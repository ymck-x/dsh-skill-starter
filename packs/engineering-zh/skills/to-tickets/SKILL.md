# 拆票

输入是一份计划、一份规格，或者当前这场对话。输出是一组票据：一张票据就是一条穿过各层的窄而完整的路径，做的人从用户视角能自己验证它成了没有，并且整张票据能塞进一个全新的上下文窗口。

先读 `docs/agents/issue-tracker.md`，按里面的约定写票。它不存在时，用 `skill` 工具加载 `setup-tickets` 建好再继续。

## 一张合格的票据

- **一条曳光弹**：从用户能碰到的入口，一路穿到它需要的每一层，最后给出一个可观察的结果。宁可窄，不要断。按层横切（先写完所有数据层，再写完所有接口层）不算一张票。
- **一个全新的上下文窗口装得下**：一个不知情的执行者只读这张票和它引用的文件，就能从头做到尾，不必回头翻这次对话。
- **有自己的反馈回路**：票面写清哪条命令变红说明还没做完、变绿说明做完了。这条命令写不出来，说明这张票的边界没切对。
- **是个深模块**：接口小、行为多。票面写决策本身，不写文件路径和代码片段。

## 拆的步骤

1. **列出用户能看见的结果**，一条一行。这是曳光弹的候选列表。
2. **给每条结果标出它要碰的层和缝**，看哪几条共享同一段改动。
3. **按依赖排顺序**，写清每张票被谁阻塞。能并行的两条不要写成串行。
4. **逐张压缩体量**，压到能进上下文窗口的舒适区为止。压不下去就按「先在最窄的一条路上跑通，再补其余情况」再切一刀。
5. **检查阻塞图**：它该是一张稀疏的有向图，而不是一条长链。长链说明还能并行的部分没找出来。

## 拆不出一刀的时候：扩张-收缩

有一类改动是一处机械修改波及整个代码库：动了旧形式，所有调用点必须同时跟上，中间任何一刻都拿不到绿灯。这种不必硬切成互相独立通过的小票，改走扩张-收缩：

1. **扩张**：加进新形式，旧形式原样留着，两边同时可用。这一票的反馈回路是「新形式可用，旧行为没坏」。
2. **分批迁移**：按影响半径分批把调用点搬到新形式上，每批一票，每批都让全套回路保持绿。批与批之间可以并行，也可以共用同一个集成分支。
3. **收缩**：确认没有调用点留在旧形式上之后，删掉旧形式。

这种情况下，中间各票只在「新形式可用 + 旧行为没坏」这个口径上承诺绿灯，**整个改动的绿灯只在最后那张集成验证票上承诺**。票面写明共用哪个集成分支，以及谁负责最后那次全量验证。

## 完成标准

- 每张票都有一条能独立变红、独立变绿的反馈回路。
- 每张票都写了「阻塞于 #N」，或者明确写了无人阻塞。
- 从最后一张票往回看，用户能看见的结果全都有人负责。

## 先摆给用户看

写任何文件之前，把提议的拆分按顺序摆出来：每张票一行，写清它交付什么、阻塞于谁。然后**一轮问一批**，一次问完：

- 粒度对不对：哪张太大，一个上下文窗口装不下？哪张太小，单独做出来看不见任何变化？
- 阻塞关系对不对：哪两条本该并行却被写成了串行？哪条依赖漏了？
- 扩张-收缩那一组要不要共用集成分支？最后那张集成验证票谁来负责？

用户认可之后，再按 `docs/agents/tickets/<编号>-<短名>.md` 一个文件一张地写下去。文件顶部一行状态，默认 `待确认`；当场确认过的写 `已就绪`。编号从 1 递增，每张票写明「阻塞于 #N」，无人阻塞就写「无」。

要让这次改动先变简单再做（预重构），或者想看一张填好的票据样例，读同目录的 `PREFACTOR.md`。
