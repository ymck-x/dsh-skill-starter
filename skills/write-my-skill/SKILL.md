把用户口述的做法变成一份能反复使用的技能文件。

## 步骤

### 1. 先问清楚四件事

一次问完，不要挤牙膏。用户已经说过的就别再问。

- 什么时候该用它（触发场景，尽量用用户自己的说法）
- 它要做什么（步骤）
- 做到什么算完成（一个能检查的标志）
- 什么不该做（边界、反例、上次踩过的坑）

### 2. 起名字

英文小写加连字符，例如 `code-review`、`weekly-report`。用用户平时喊它的那个词，不要自造术语。

### 3. 写文件

写到用户技能目录下：`<技能名>/SKILL.md`。用户技能目录是 `~/.dsh/skills`，Windows 上是 `C:\Users\<用户名>\.dsh\skills`。目录不存在就先建。

格式：

```
---
name: <技能名>
description: "<一句话。要让 AI 自己判断何时使用，就把触发场景写进去，例如「当用户要求……时使用」。只在用户手打 /技能名 时才用，就写一句给人看的说明，不要写触发词。>"
---

<正文>
```

正文要求：

- 用祈使句，直接写做什么，不要写「我应该……」。
- 只写这个流程特有的东西。通用常识（要写好代码、要注意安全）不用写。
- 有判断分叉的地方写成列表或表格，不要埋在段落里。
- 一屏以内。超过一屏，应该拆成两个技能。

### 4. 报告

写完告诉用户三件事：文件放在哪、怎么改（直接编辑那个 Markdown 文件，存盘后下一步就生效）、怎么手动调用（`/技能名`）。

## 不要做

- 不要覆盖用户已有的同名技能，先问一句。
- 不要顺手改别的技能。
- 不要在正文里复述用户的原话当作步骤，要提炼成动作。
